# probe five

| Step | Command | Observed |
|---|---|---|
| baseline | `vigil scan` | clean, no findings |
| dry run | `vigil scan --rules killpack.json` | detected; process **still alive** |

Two real bugs were found this way and fixed, both of which passed an initial
review:

1. **Every response was a silent no-op.** `Detection` rebuilt its `Process` from
   a context dict the process-scoped path never populated, so each kill logged
   `skipped: no process to kill` while the audit trail looked healthy.
2. **The caller's audit log was discarded.** `AuditLog` defined `__len__`, so an
   empty log was falsy and `audit or AuditLog()` substituted a fresh instance.

## Limitations of the response path

- `block` shells out to `iptables` and needs root. A non-root run reports the
  failure rather than raising, but it will not block.
- `quarantine` sends `SIGSTOP` and renames the binary to `*.vigil-quarantine`
  rather than deleting it.
- Killing a process loses its memory.
- Policy checks are per-action, not per-host. There is no global stop brake.
- There is no rollback. A wrong kill is not undoable.

## Legal and authorised use

Run this on hosts you own or are explicitly authorised to administer. It reads
process and connection state and it can terminate processes.
