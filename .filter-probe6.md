# probe six

## What it detects

The shipped pack covers seven behaviours:

| Rule | Severity | Action |
|---|---|---|
| `proc-deleted-binary` — binary deleted from disk, process still running | critical | alert |
| `proc-tmp-exec` — executable in a world-writable directory | high | alert |
| `proc-shell-from-tmp` — interpreter with a temp-dir binary | high | alert |
| `conn-tmp-process-egress` — temp-dir process with established egress | high | alert |
| `proc-crypto-miner-name` — known miner family names | high | quarantine |
| `proc-netcat-listen` — netcat/socat in listen mode | medium | alert |
| `conn-bare-ip-high-port` — bare-IP traffic on an ephemeral port | medium | alert |

**It does not detect:**

- **Anything that needs kernel telemetry.** No eBPF, no auditd integration, no
  fanotify. A rootkit that hides from `/proc` hides from vigil completely.
- **Fileless execution** beyond the deleted-binary case.
- **Lateral movement.** It has no memory between runs.
- **Credential access.** Nothing here reads `/etc/shadow` or keyrings.
- **Persistence mechanisms** — cron, systemd units, shell profiles, LD_PRELOAD.
- **Windows and macOS.** `/proc` only.
- **Container escapes.**

The rules are heuristics. Treat every finding as a lead, not a verdict.
